# 🎯  AKS Cluster Access — Industry Standard (Deadpool Edition)

  "You have the cluster. Now let's get in without getting fired."

  ---

  🔑  Step 1: Get Credentials (AAD-Integrated)

  # Why: Old school `--admin` = walking around with your password on a billboard.
  # AAD = SSO + audit trail. Your security team will finally hug you.
  az aks get-credentials --resource-group <rg> --name <cluster> --overwrite-existing
  ```bash
  kk_lab_user_main-e9ba0906ce0c4f5 [ ~ ]$ az aks get-credentials --resource-group kml_rg_main-e9ba0906ce0c4f57 --nkodekloud-demo --overwrite-existing
  Merged "kodekloud-demo" as current context in /home/kk_lab_user_main-e9ba0906ce0c4f5/.kube/config
  ```
  # Behind the scenes → uses kubelogin for AAD token exchange
  `kubelogin convert-kubeconfig -l azurecli`
  ✅  Verify → kubectl get nodes

  ---

  🔐  Step 2: Role Assignments FIRST, kubectl SECOND

  # Why: Default cluster has zero access for normal humans.
  # Industry = least privilege. You don't give God-mode to interns.
  ```bash
  az role assignment create \
    --assignee {user-email-or-objectId} \
    --role "Azure Kubernetes Service RBAC Reader" \
    --scope /subscriptions/{sub_name}/resourcegroups/{rg}/providers/Microsoft.ContainerService/managedClusters/{cluster}
  ```

  🚪  Step 3: Private Cluster? Use Bastion / Jumpbox

  # Why: Public API server = every script kiddie says hi.
  # Private cluster + Bastion = VPN-tier access without VPN pain.
  ```bash
  az network bastion create --name aks-bastion ...

  ```

  az aks update --api-server-vnet-integration enabled
  ✅  SSH to jumpbox → az aks get-credentials → kubectl

  ---

  ⚡  Step 4: Just-In-Time Access (PIM)

  # Why: Standing admin access = "I YOLO'd prod at 2 AM."
  # PIM = request → approve → time-bound access → auto-revoke.
  az aks update --enable-azure-rbac
  az role assignment create --role "Azure Kubernetes Service RBAC Cluster Admin" \
    --assignee <user> --scope <cluster> --condition "PimEligible=true"

  ---

  🧑‍✈️ Step 5: Service Account for CI/CD

  # Why: Pipelines shouldn't log in as humans. Or as admins. Just. No.
  # Workload Identity = pod → AAD → Azure resources. No secrets. Chef's kiss.
  az aks update --enable-oidc-issuer --enable-workload-identity
  az federated-identity create ...
  ✅  In pod → kubectl auth works without keys, env vars, or tears.

  ---

  🛡️  Step 6: Lock the API Server

  # Why: API server = kingdom keys. Don't leave it on the dashboard.
  # API Server VNet Integration → only reachable from inside your vnet
  az aks update --api-server-vnet-integration enabled \
    --subnet <subnet-id>

  ---

  🌐  Step 7: Remote Dev (Lens / Cloud Shell)

  # Why: Laptop died? Plane WiFi trash? Cloud Shell doesn't care.
  # Azure Cloud Shell has az + kubectl preinstalled. Lifesaver.
  az cloud-shell --mount <storage-account>
  ✅  OR Lens IDE → kubeconfig import → GUI cluster surfing.

  ---

  🕵️  Step 8: Audit Everything

  # Why: "Who deleted prod?" — without audit logs, you're guessing.
  az monitor diagnostic-settings create \
    --resource <cluster-id> --logs '[{"category":"kube-audit","enabled":true}]'
  ✅  Send to Log Analytics → query who did what, when, and why.

  User → AAD SSO → RBAC Role Check → kubelogin → kubectl

  ❌  Don't Do This (the Hall of Shame)

  - ❌  --admin flag for daily work → audit logs = empty, vibes = chaos
  - ❌  Long-lived service principal keys → leaked = game over
  - ❌  Cluster-admin to everyone → "we have 47 admins, lol"
  - ❌  Public API server + weak NSG → congrats, you mined crypto for someone
